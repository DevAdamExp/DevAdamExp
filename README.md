## 01 · If you only read one thing

**A visa CRM, powered by AI. But the model never makes the final call.**

A visa consultancy ran every case on spreadsheets and WhatsApp and checked eligibility by hand. A model can read a CV quickly, but if it says yes when the answer is no, a real person loses months and money. So the model only reads and drafts:

> **01 · The model reads.** It parses the CV, suggests countries and digs up official requirements.<br>
> **02 · Rules decide.** A rule file per country makes the eligibility call.<br>
> **03 · A person signs off.** Nothing positive reaches a client without approval.

**2,600+** backend tests gate every release &nbsp;·&nbsp; **4-eyes**, nobody approves their own work &nbsp;·&nbsp; **paid-only** models see personal data

[Read the case study →](https://adam-dev-ai-architect.vercel.app/projects/visa-crm) &nbsp;<sub>Private build, walkthrough on request.</sub>

## 04 · How I work

Not principles, just what I actually do.

- **I write it down first.** Before I code, I sketch the data, the screens and what can go wrong.<br><sub>*In practice:* the medication app shipped with about 30 docs: runbooks, test plans, a privacy assessment.</sub>
- **Small commits, every day.** Nothing sits half-done, and reviews stay easy.<br><sub>*In practice:* around 1,000 commits on the CRM in its first few months.</sub>
- **Tests before trust.** If it handles money, bookings or health data, it doesn’t ship until a test covers it.<br><sub>*In practice:* 2,600+ backend tests on the CRM, and a 48-step end-to-end suite on the app.</sub>
- **AI drafts, people decide.** Models are good at reading and drafting. Final calls go to rules or a person.<br><sub>*In practice:* eligibility comes from rule files per country, and a consultant approves every “yes”.</sub>
